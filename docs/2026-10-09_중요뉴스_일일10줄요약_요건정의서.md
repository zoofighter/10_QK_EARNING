## 1. 추진 배경 및 목적

### 1.1 배경 및 현황 문제점
1. **정보 과부하 (Information Overload)**:
   * 현재 37개 AI 밸류체인 기업을 대상으로 Google News, Yahoo Finance, 네이버 금융 등을 통해 매일 수백~수천 건의 기사가 `news` 테이블에 적재되고 있습니다.
   * 사용자가 대시보드에 접속했을 때 기업별 개별 뉴스를 일일이 찾아 읽어야 하므로, **"오늘 전체 AI 반도체 시장에서 가장 중요한 일이 무엇인가?"**를 한눈에 파악하기 어렵습니다.
2. **시장 시그널의 즉시성 부족**:
   * 빅테크 실적 발표, 엔비디아/빅테크 메가 계약, HBM/eSSD 수급 동향, 관세 및 수출 통제 등 시장을 움직이는 핵심 시그널이 일반 홍보성/단신 기사에 묻히는 현상이 발생합니다.

### 1.2 추진 목적
* 최근 24시간 동안 수집된 글로벌 뉴스를 지능형 알고리즘 및 요약 엔진을 통해 필터링하여, **정확히 10줄(Top 10 Bulletins)**로 압축된 **일일 경영진 핵심 브리핑(Daily Top 10 Executive Briefing)**을 제공합니다.
* C-Level 경영진, 펀드매니저, 반도체 애널리스트가 **3분 안에 당일 AI 밸류체인 핵심 변동사항과 시사점을 완벽히 파악**할 수 있도록 지원합니다.

## 3. 기능 요구사항 (Functional Requirements)

### 3.1 [FR-1] 뉴스 데이터 수집 및 1차 필터링
* **분석 대상 윈도우**: 생성 시점 기준 최근 24~48시간 이내에 수집된 `news` 테이블의 전체 기사.
* **노이즈 필터링**:
  * 단순 시황 단신, 주가 등락 수치만 나열한 기사, 광고성 기사 제거.
  * 중복 기사 클러스터링: 유사한 제목/내용의 기사는 TF-IDF / 코사인 유사도로 묶고 대표 기사 1건으로 압축.

### 3.2 [FR-2] 밸류체인 영향도 스코어링 (Impact Scoring Algorithm)
기사별 중요도 점수($Score$)를 산출하여 상위 후보군을 선별합니다:

$$\text{Total Score} = \text{Base Score} + \text{Keyword Weight} + \text{Tier Weight} + \text{Coverage Weight}$$

| 평가 요소 | 가중치 기준 | 점수 |
| :--- | :--- | :---: |
| **핵심 키워드 가중치** | HBM(HBM3E, HBM4), CapEx(설비투자), 독점/수주(Contract), 퀄(Qualification), 실적 서프라이즈, 수출 통제, 전력/냉각 | +20 ~ +40점 |
| **언론사/출처 신뢰도** | Tier 1 매체 (Reuters, Bloomberg, 연합뉴스, FT, 한국경제, WSJ 등) | +15 ~ +25점 |
| **다수 매체 보도 빈도** | 동일 이슈가 3개 이상 독립 언론사에서 동시 보도된 경우 (Clustered Coverage) | +20점 |
| **기업 중요도** | 핵심 레이어 앵커 기업 (NVDA, TSM, SK하이닉스, 삼성전자, MSFT 등) | +10점 |

### 3.3 [FR-3] 다양성 및 편향 방지 규칙 (Diversity Rule)
* **단일 기업 쏠림 방지**: 특정 기업(예: 엔비디아) 관련 뉴스가 아무리 많더라도, **10개 항목 중 최대 2개 항목**까지만 허용.
* **레이어 커버리지 분산**:
  * `L2 하이퍼스케일러`: 1~2건
  * `L3 AI 컴퓨팅/가속기`: 1~2건
  * `L4 파운드리/장비`: 1~2건
  * `L5 메모리/스토리지`: 2~3건 (프로젝트 핵심 집중 영역)
  * `L6~L8 네트워크/인프라/전력`: 2~3건
* 이를 통해 특정 분야에 편중되지 않는 **전체 AI 밸류체인 조망**을 완성합니다.

### 3.4 [FR-4] 10줄 정제 및 문장 생성 엔진 (Generation Pipeline)
1. **1단계 (후보 추출)**: 필터링 및 스코어링을 거쳐 레이어별 상위 25~30건 후보 추출.
2. **2단계 (핵심 사실 추출)**:
   * 주어(기업명/티커), 서술어(어떤 이벤트가 발생했는가), 수치 팩트(금액, 용량, 단가 변동률 등), 영향(공급망 시사점) 구조화.
3. **3단계 (10줄 빌더)**:
   * **LLM 모드**: Gemini / 로컬 모델 프롬프트를 통해 10개 정형화된 한국어 불릿으로 변환.
   * **Rule-based Fallback 모드**: LLM API 호출 불가/지연 시, 사전 정의된 템플릿과 고득점 기사 메타데이터를 결합하여 1초 이내 무중단 자체 생성.

### 3.5 [FR-5] 정기 스케줄링 및 수동 트리거
* **자동 생성 스케줄**:
  * **오전 07:30 KST (Morning Edition)**: 미국 증시 마감 후 밤사이 발생한 글로벌 빅테크 및 외신 종합.
  * **오후 18:30 KST (Evening Edition)**: 한국/대만/일본 아시아 증시 마감 및 국내 메모리/공시 종합.
* **온디맨드 수동 생성**:
  * 관리자 및 사용자가 원할 때 즉시 최신 기사를 취합하여 10줄 요약을 재산출할 수 있는 버튼 제공.

### 3.6 [FR-6] 일자별 히스토리 아카이빙
* 매일 생성된 10줄 요약은 DB에 영구 저장되어, 과거 특정 날짜(어제, 지난주, 특정 실적 발표일 등)의 브리핑을 캘린더/날짜 선택기로 즉시 역추적할 수 있어야 함.

## 4. 데이터 모델 설계 (Data Schema)

### 4.1 `daily_news_digest` 테이블
일자별 10줄 요약 결과를 버전 및 세션별로 저장하는 테이블:

```sql
CREATE TABLE IF NOT EXISTS daily_news_digest (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    digest_date   TEXT NOT NULL,               -- 'YYYY-MM-DD'
    edition       TEXT NOT NULL DEFAULT 'MORNING', -- 'MORNING', 'EVENING'
    title         TEXT NOT NULL,               -- '2026년 10월 9일 AI 밸류체인 핵심 뉴스 Top 10'
    items_json    TEXT NOT NULL,               -- JSON 배열 (10개 상세 항목)
    summary_md    TEXT NOT NULL,               -- 10줄 정형 마크다운 텍스트
    generated_by  TEXT NOT NULL DEFAULT 'HYBRID', -- 'LLM', 'RULE_ENGINE', 'HYBRID'
    source_count  INTEGER DEFAULT 0,           -- 요약에 참조된 기사 총수
    created_at    TEXT DEFAULT (datetime('now')),
    updated_at    TEXT DEFAULT (datetime('now')),
    UNIQUE (digest_date, edition)
);

CREATE INDEX IF NOT EXISTS idx_digest_date_ed ON daily_news_digest(digest_date DESC, edition);
```

#### `items_json` 저장 필드 규격:

## 5. REST API 명세 (API Specification)

### 5.1 최신/특정일자 10줄 요약 조회
* **Endpoint**: `GET /api/news/daily-top10`
* **Query Parameters**:
  * `date`: (선택) `YYYY-MM-DD` (기본값: 오늘 날짜)
  * `edition`: (선택) `MORNING` 또는 `EVENING` (기본값: 최신 세션)
* **Response (JSON)**:
  ```json
  {
    "status": "success",
    "data": {
      "digest_date": "2026-10-09",
      "edition": "MORNING",
      "title": "2026년 10월 9일 AI 반도체 밸류체인 핵심 뉴스 Top 10 브리핑",
      "updated_at": "2026-10-09 07:30:15",
      "total_items": 10,
      "items": [
        {
          "rank": 1,
          "layer_code": "L5_MEMORY",
          "ticker": "000660.KS",
          "company_ko": "SK하이닉스",
          "line_text": "01. [L5 000660.KS] SK하이닉스, 엔비디아 루빈(Rubin)향 HBM3E 12단 독점 공급 승인 — 2027년까지 메모리 캐파 완판 지속",
          "ref_url": "https://..."
        }
      ],
      "markdown_text": "..."
    }
  }
  ```

### 5.2 10줄 요약 즉시 생성 트리거 (온디맨드)
* **Endpoint**: `POST /api/news/daily-top10/generate`
* **Request Body**:
  ```json
  {
    "date": "2026-10-09",
    "force": true
  }
  ```
* **Response (JSON)**:
  ```json
  {
  ```

## 6. UI / UX 디자인 요구사항

### 6.1 노출 위치 및 레이아웃
1. **대시보드 메인 Overview 상단** 또는 **뉴스 탭 전면 배너**:
   * 대시보드 진입 시 스크롤 없이 바로 시선을 끄는 **프리미엄 브리핑 카드** 형태로 배치.
2. **시각적 계층 구조**:
   * 헤더: `⚡ 오늘의 AI 밸류체인 핵심 뉴스 Top 10 브리핑` 타이틀 + 일자 배지 + 새로고침 버튼.
   * 우측 상단 유틸리티: `📋 클립보드 복사` (슬랙/보고서용 10줄 마크다운 즉시 복사), `📅 일자 선택 드롭다운`.
3. **10줄 리스트 카드 디자인**:
   * 순위 넘버링(01 ~ 10): 골드/네온 액센트 컬러 뱃지.
   * 레이어 태그: 기존 디자인 시스템의 고유 색상 뱃지 적용 (`L5_MEMORY` 주황색, `L3_COMPUTE` 보라색, `L2_HYPERSCALER` 청록색).
   * 텍스트: 볼드 처리된 핵심 사실 + 구분선(`—`) + 영향도 요약.
   * 인터랙션: 각 줄 클릭 시 해당 기업 워크스페이스로 이동하거나 원문 기사 새 탭 열기 지원.

## 7. 비기능적 요구사항 (Non-Functional Requirements)

1. **응답 속도 (Performance)**:
   * `daily_news_digest` 테이블 캐싱을 통해 일반 사용자의 `GET /api/news/daily-top10` 호출 시 **50ms 이내** 초고속 응답.
2. **장애 내구성 (High Availability & Fallback)**:
   * 외부 LLM API가 다운되거나 응답이 지연(타임아웃 5초 초과)될 경우, 자체 룰베이스 알고리즘으로 자동 절체(Failover)되어 빈 화면이 발생하지 않도록 보장.
3. **일관성 및 정합성 (Consistency)**:
   * 매일 동일 날짜/에디션에 대해서는 멱등성(Idempotency) 유지.
