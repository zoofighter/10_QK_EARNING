## 4. 어닝 캘린더 & D-Day 타임라인 데이터 소스 및 시스템 아키텍처

사용자가 대시보드에서 조회하는 **"어닝 캘린더 & D-Day 타임라인"**의 데이터 원천 및 내부 처리 흐름은 다음과 같습니다.

### 4.1 데이터 흐름 구조 (Data Flow)

```text
[1. 원본 데이터 소스 (Data Sources)]
  • 각 기업 공식 IR (Investor Relations) 실적 발표 공지
  • Yahoo Finance Earnings Calendar (yfinance.Ticker.calendar)
  • SEC EDGAR Form 8-K (실적 발표 완료일 actual_date)
         │
         ▼
[2. 로컬 데이터베이스 (Persistence)]
  • SQLite DB: data/qk_earning.db
  • 테이블: earning_calendar (expected_date, actual_date, call_time_et, status)
         │
         ▼
[3. 백엔드 REST API (Business Logic)]
  • GET /api/calendar (전체 34개사 타임라인 정렬 반환)
  • GET /api/companies/<ticker>/full (개별 기업 실적 D-Day 반환)
  • D-Day 동적 계산: (expected_date - date.today()).days ➔ D-Day, D-n, D+n
         │
         ▼
[4. 프론트엔드 UI (Presentation)]
  • static/js/app.js (loadCalendar, loadMasterData)
  • static/index.html (#mode-calendar, #tbody-calendar-full, 사이드바 D-Day 뱃지)
```

### 4.2 구체적인 위치 및 코드 내역

1. **프론트엔드 호출부 (`static/js/app.js`)**:
   * **`loadCalendar()` (1620행)**:
     - `fetch('/api/calendar')`를 호출하여 전체 캘린더 테이블을 렌더링.
     - 당일은 `🔥 D-Day`, 7일 이내는 `⚡ D-n`, 예정일 경과 시 `D+n` 뱃지 자동 생성.
   * **`loadMasterData()` (205행)**:
     - 좌측 사이드바 34개 기업명 옆에 실적 임박 D-Day 태그(예: `MSFT ⚡D-7`)를 바인딩.
2. **백엔드 REST API (`app/routes/api.py`)**:
   * **`GET /api/calendar` (279~302행)**:
     ```sql
     SELECT ec.*, e.ticker, e.name_en, e.name_ko, e.layer_code
     FROM earning_calendar ec
     JOIN entity e ON ec.entity_id = e.id
     ORDER BY ec.expected_date ASC
     ```
     - 서버 기준 현재 날짜(`date.today()`)와 `expected_date`의 차이를 비교하여 `days_left` 및 `d_day` 라벨을 동적으로 계산.
   * **`GET /api/companies/<ticker>/full` (1403~1435행)**:
     - 해당 기업의 가장 최근/차기 실적 일정을 조회하여 상단 헤더 Quick KPI 카드에 전달.
3. **데이터베이스 스키마 (`data/qk_earning.db`)**:
   * **`earning_calendar` 테이블**:
     ```sql
     CREATE TABLE earning_calendar (
         id INTEGER PRIMARY KEY AUTOINCREMENT,
         entity_id INTEGER NOT NULL,
         fiscal_year TEXT NOT NULL,       -- 회계연도 (예: '2026')
         fiscal_quarter TEXT NOT NULL,    -- 분기 (예: 'Q1', 'Q2')
         expected_date TEXT NOT NULL,     -- 발표 예정일 (예: '2026-12-10')
         actual_date TEXT,                -- 실제 발표일 (예: '2026-09-10')
         call_time_et TEXT,               -- 컨콜 시간 (예: '17:00')
         status TEXT DEFAULT 'UPCOMING',  -- UPCOMING, CONFIRMED, COMPLETED
         created_at TEXT DEFAULT (datetime('now')),
         FOREIGN KEY (entity_id) REFERENCES entity(id) ON DELETE CASCADE,
         UNIQUE (entity_id, fiscal_year, fiscal_quarter)
     );
     ```
4. **현재 적재된 기초 데이터 원천 (`scripts/seed_entities.py`)**:
   * 초기 데이터는 `scripts/seed_entities.py` 내의 `CALENDAR_SEEDS` 딕셔너리에 정의되어 있으며, 월가 증권사 및 각 기업 IR 발표 일정을 기준으로 등록되어 있습니다.
5. **외부 자동 수집 파이프라인 연계 방안**:
   * Yahoo Finance API(`yfinance.Ticker.calendar`)를 정기 스케줄러에 연동하면 사람이 입력하지 않아도 실시간 차기 실적발표일(`Earnings Date`)과 컨센서스(EPS/매출)를 34개사 전체에 자동 갱신할 수 있습니다:
     ```python
     import yfinance as yf
     earnings_date = yf.Ticker("ORCL").calendar.get('Earnings Date')[0]
     # -> datetime.date(2026, 12, 11) 자동 추출
     ```
