## 1. 현황 및 문제 원인

### 1.1 현황 진단
* `data/qk_earning.db`의 `news` 테이블에는 총 8,392건의 기사가 적재되어 있으나, 기존 `b_0826_news_research/db/news.sqlite` 마이그레이션 대상이었던 **12개 대형 기업**(삼성전자, SK하이닉스, NVDA, MSFT, AAPL, AMD, META, GOOGL, AMZN, ASML, TSM, MU) 위주로만 데이터가 구성되어 있었습니다.
* 나머지 **22개 밸류체인 기업**(브로드컴 AVGO, 코어위브 CRWV, 오라클 ORCL, 버티브 VRT, 아리스타 ANET, Arm ARM, 인텔 INTC, 램리서치 LRCX, KLA KLAC, 앰코 AMKR, 키옥시아 6600.T, 웨스턴디지털 WDC, 마벨 MRVL, 코히어런트 COHR, 네비우스 NBIS, 소프트뱅크 9984.T, 스페이스X SPACEX, 이튼 ETN, GE버노바 GEV, 슈나이더 SBGSF 등)은 DB 내 기사 수가 **0건**으로 비어 있어 화면에서 뉴스가 하나도 보이지 않는 문제가 발생했습니다.

## 2. 채택된 해결 방안: [방안 2] 전체 34개사 일괄 시드 수집 및 정기 스케줄러 배치

### 2.1 아키텍처 개요
1. **RSS 수집 파이프라인 (`app/services/news_collector.py`)**:
   * **Google News RSS 피드**: `{한글기업명} {영문기업명} {티커}` 기반 국내외 주요 언론사(연합뉴스, 한국경제, 매일경제, Reuters, Bloomberg, WSJ 등)의 실시간 헤드라인 및 스니펫 파싱.
   * **Yahoo Finance RSS 피드**: 미국 증시 상장사 전 종목의 월가 금융/투자 전문 속보 파싱.
   * **데이터 정규화 & 중복 제거**: URL 해시 기반 중복 제거, HTML 엔티티 제거, 발행일자(`YYYY-MM-DD HH:MM:SS`) 통일, 관련도 점수(Score) 자동 산정.
2. **일괄 시드 적재 스크립트 (`scripts/seed_company_news.py`)**:
   * `entity` 테이블의 34개 기업 마스터를 조회하여, 뉴스가 부족하거나 없는 기업을 대상으로 최신 기사 30~50건씩 일괄 크롤링 및 DB INSERT.
   * 한국 거래소 티커(`.KS`), 일본 거래소 티커(`.T`)의 접미사 호환 매핑 지원.
3. **백그라운드 스케줄러 연동 (`app/services/report_scheduler.py`)**:
   * 매일 정기 스케줄(개장 전 08:30 / 장 마감 후 18:30)에 신규 뉴스를 증분 자동 수집하도록 배치 등록.
4. **API 조회 고도화 (`app/routes/api.py`)**:
   * `/api/companies/<ticker>/news`에서 티커 접미사(`.KS`, `.T`) 매핑 및 한글명/영문명 다각도 검색 쿼리 지원.

## 3. 구현 세부 규격

### 3.1 `news` 테이블 스키마
```sql
CREATE TABLE IF NOT EXISTS news (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    url          TEXT UNIQUE NOT NULL,
    title        TEXT NOT NULL,
    snippet      TEXT,
    source       TEXT NOT NULL,
    company      TEXT NOT NULL,
    ticker       TEXT,
    query        TEXT,
    score        INTEGER DEFAULT 0,
    published    TEXT,
    collected_at TEXT NOT NULL
);
```

## 4. 실제 구현 완료 내역 (2026-10-08)

### 4.1 뉴스 수집기 서비스 (`app/services/news_collector.py`)
* **Google News RSS & Yahoo Finance RSS 연동**: API 키 없이 안정적으로 국내외 주요 언론사 기사 크롤링 및 파싱.
* **티커/사명 스마트 매핑**: `005930.KS`(삼성전자), `6600.T`(키옥시아), `CRWV`(코어위브), `AVGO`(브로드컴), `VRT`(버티브) 등 한글명·영문명·심볼 동시 쿼리 지원.
* **HTML 클리닝 & 날짜 표준화**: `email.utils.parsedate_to_datetime`을 통해 `YYYY-MM-DD HH:MM:SS` 표준 포맷 변환 및 HTML 태그·특수 엔티티 제거.
* **중요도 스코어링 & 중복 제거**: 기사 URL 해시 기준 UNIQUE 무결성 보장 및 75~90점 가중치 점수 산정.

### 4.2 34개사 일괄 시드 수집 실행 (`scripts/seed_company_news.py`)
* 누락되어 있던 **22개 전 기업 대상 총 877건의 중요 뉴스 신규 수집 및 DB INSERT 완료**:
  * `ORCL`(+40건), `CRWV`(+40건), `NBIS`(+39건), `AVGO`(+40건), `ARM`(+40건), `INTC`(+40건), `AMAT`(+40건), `LRCX`(+40건), `KLAC`(+40건), `ASX`(+40건), `AMKR`(+40건), `WDC`(+40건), `6600.T`(+38건), `MRVL`(+40건), `COHR`(+40건), `ANET`(+40건), `SPACEX`(+40건), `9984.T`(+40건), `VRT`(+40건), `ETN`(+40건), `GEV`(+40건), `SBGSF`(+40건)
  * **현재 `news` 테이블 총 보유 기사 수: 9,269건 달성** (모든 34개 기업에 38~866건의 풍부한 뉴스 보유).

### 4.3 API 실시간 자동 수집 Fallback 구현 (`app/routes/api.py`)
* 엔드포인트: `GET /api/companies/<ticker>/news`
* **Base Ticker 매칭**: `clean_ticker = ticker.split('.')[0]` 지원으로 `005930.KS` ↔ `005930` 완벽 호환.
* **실시간 자동 Fallback & Refresh**:
  * DB 내 기사 수가 0건이거나 쿼리 파라미터 `?refresh=true`가 인입될 경우, `NewsCollector().collect_for_entity()`가 백엔드에서 즉시 실시간 수집을 실행하여 DB 저장 후 최신 기사를 반환 (뉴스 공백 발생 원천 차단).

### 4.4 정기 백그라운드 스케줄러 등록 (`app/services/report_scheduler.py`)
* **오전 07:00 KST**: 34개사 일일 아침 중요 뉴스(Google/Yahoo RSS) 수집 및 동기화.
* **오후 19:00 KST**: 34개사 일일 저녁 중요 뉴스(Google/Yahoo RSS) 수집 및 동기화.
* **수동 즉시 실행 API**: `POST /api/scheduler/run-now`에 `{"job": "NEWS"}` 호출 시 즉시 34개사 최신 뉴스 배치 실행 지원.

### 4.5 프론트엔드 "🔄 최신 수집" 실시간 버튼 추가 (`static/index.html`, `static/js/app.js`)
* `📰 중요 뉴스` 탭 상단 출처 필터 우측에 `🔄 최신 수집` 버튼을 배치하여, 사용자가 언제든 원클릭으로 해당 기업의 최신 뉴스를 실시간 재수집(`?refresh=true`)할 수 있도록 구현.
