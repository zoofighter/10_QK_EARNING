**문서 버전:** v1.0  
**작성일:** 2026-10-08  
**대상 시스템:** `b_0917_10_QK_EARNING`  
**대상 화면:** `개요` (`tab-overview`)  
**관련 파일:** `static/index.html`, `static/js/app.js`, `static/css/style.css`, `app/routes/api.py`

## 1. 문서 목적

현재 QK_EARNING 개요 화면을 단순한 데이터 보유 현황 화면에서 **AI·반도체 밸류체인의 주요 변화를 빠르게 판단하는 데일리 인텔리전스 화면**으로 개편하기 위한 기능, 데이터, UI/UX 및 검수 요건을 정의한다.

개편 화면은 사용자가 접속 후 10초 안에 다음 질문에 답할 수 있어야 한다.

1. 오늘 새로 발생한 중요한 신호는 무엇인가?
2. 다음 실적 발표는 언제이며 무엇을 확인해야 하는가?
3. 실적, 컨센서스, 주가 및 선행지표에서 의미 있는 변화가 발생했는가?
4. 그 변화가 밸류체인의 어느 레이어와 기업에 연결되는가?
5. 데이터는 언제 갱신됐으며 신뢰할 수 있는가?

## 2. 개편 원칙

### 2.1 제품 역할

개요 화면의 역할을 다음과 같이 정의한다.

> **공시·실적·시장·산업 데이터를 한 화면에서 요약하고, 사용자가 다음 분석 행동을 선택하도록 돕는 의사결정 관제 화면**

### 2.2 정보 우선순위

화면 정보는 다음 순서로 배치한다.

```text
긴급 신호
 → 오늘의 핵심 현황
 → 예정된 실적 이벤트
 → 실적·컨센서스 변화
 → 산업 선행지표
 → 밸류체인 영향
 → 최근 원문과 데이터 품질
```

### 2.3 기본 설계 원칙

- 전체 데이터 건수보다 **변화, 이상, 일정 및 영향**을 우선 표시한다.
- 모든 요약 수치는 상세 화면으로 이동할 수 있어야 한다.
- Actual, Consensus, Forecast를 색상과 라벨로 명확히 구분한다.
- 수치에는 기준일, 단위, 출처 및 갱신 시각을 표시한다.
- 데이터가 없을 때 가상의 값을 표시하지 않는다.
- 한 화면에서 모든 내용을 펼치지 않고 중요도 순으로 요약한다.
- 기존 다크 테마와 Vanilla HTML/CSS/JavaScript 구조를 유지한다.

## 3. 현재 화면 분석

### 3.1 현재 구성

현재 개요 화면은 다음 요소로 구성된다.

- 대상 기업 수
- 수집 완료 공시 수
- 주가 추적 기업 수
- 다음 실적 발표 D-Day
- 다가오는 어닝 일정
- 밸류체인 레이어별 기업 수
- 최근 SEC Filing 목록

### 3.2 개선 필요사항

| 구분 | 현재 문제 | 개선 방향 |
|---|---|---|
| KPI | 누적 건수 중심이라 투자·분석 판단에 직접 도움이 적음 | 금일 변화와 이상 신호 중심으로 변경 |
| 정보 우선순위 | 일정, 레이어, Filing이 유사한 비중으로 노출됨 | 긴급도와 영향도에 따라 계층화 |
| 실적 정보 | Beat/Miss와 분기 실적이 개요에 없음 | 최신 실적 결과와 컨센서스 차이 요약 |
| 선행지표 | 별도 탭에만 존재 | 주요 지표의 방향과 최근 변화 표시 |
| 밸류체인 | 기업 수만 표시 | 신호가 영향을 주는 레이어와 기업 표시 |
| 데이터 품질 | 갱신 시각과 수집 실패 여부를 알기 어려움 | 데이터 신선도 및 오류 상태 표시 |
| 행동 연결 | 상세 분석으로 이동하는 경로가 약함 | 각 카드에 상세보기와 필터 이동 제공 |
| 고정값 | 일부 문구와 숫자가 정적으로 표현됨 | DB/API 기반 동적 표현으로 통일 |

## 4. 대상 사용자와 주요 사용 시나리오

### 4.1 대상 사용자

- AI·반도체 산업 및 기업 실적을 추적하는 개인 분석가
- 분기 실적과 공시를 검토하는 투자 리서처
- 메모리·파운드리·가속기 밸류체인의 선행 신호를 추적하는 사용자
- 데이터 수집 상태를 관리하는 시스템 운영자

### 4.2 핵심 사용 시나리오

#### 시나리오 A: 아침 점검

사용자는 개요 화면에서 지난 24시간의 신규 공시, 컨센서스 변화, 주가 급변, 산업지표 갱신 및 수집 오류를 확인한다.

#### 시나리오 B: 실적 발표 준비

사용자는 향후 14일 내 실적 발표 기업을 확인하고, 해당 기업의 최근 컨센서스, 직전 실적, 주요 체크포인트와 관련 공시로 이동한다.

#### 시나리오 C: 실적 발표 후 검토

사용자는 최신 Beat/Miss, 매출·EPS 서프라이즈, 발표 후 주가 반응 및 관련 어닝콜 요약을 확인한다.

#### 시나리오 D: 밸류체인 신호 탐색

사용자는 메모리 가격, 한국 반도체 수출, GPU 임대가격 또는 하이퍼스케일러 Capex 변화가 어느 기업과 레이어에 연결되는지 확인한다.

#### 시나리오 E: 데이터 상태 확인

사용자는 데이터별 최종 갱신 시각과 오류를 확인하고 필요한 수집 작업을 실행한다.

### 5.1 전체 레이아웃

```text
┌─────────────────────────────────────────────────────────────┐
│ 페이지 제목 / 기준 시각 / 새로고침 / 데이터 상태           │
├─────────────────────────────────────────────────────────────┤
│ 긴급 알림 및 오늘의 핵심 신호                              │
├────────────┬────────────┬────────────┬──────────────────────┤
│ 다음 실적  │ 신규 공시  │ Beat/Miss  │ 데이터 신선도        │
├─────────────────────────┬───────────────────────────────────┤
│ 향후 14일 어닝 레이더   │ 최신 실적 및 컨센서스 변화       │
├─────────────────────────┼───────────────────────────────────┤
│ 핵심 선행지표 스냅샷    │ 밸류체인 영향 맵                 │
├─────────────────────────┴───────────────────────────────────┤
```

### 5.2 반응형 배치

- 1440px 이상: 12-column grid, 주요 영역 2열 구성
- 1024~1439px: KPI 2×2, 분석 패널 2열 유지
- 768~1023px: 주요 패널 1열, 테이블 가로 스크롤 허용
- 767px 이하: 모든 패널 1열, 표는 카드형 목록으로 전환
- 모바일에서 핵심 알림과 다음 실적 카드를 최상단에 유지

## 6. 상세 기능 요건

### OV-001. 페이지 헤더 및 기준 시각

**목적:** 화면 데이터의 현재성과 상태를 즉시 전달한다.

**표시 항목**

- 화면 제목: `AI 밸류체인 데일리 인텔리전스`
- 설명: `공시·실적·컨센서스·선행지표 통합 현황`
- 데이터 기준 시각
- 마지막 새로고침 시각
- 전체 상태: 정상, 일부 지연, 오류
- `새로고침` 버튼
- `수집 콘솔` 이동 버튼

**동작 요건**

- 새로고침은 개요 API들을 다시 호출한다.
- 동일 요청의 중복 실행을 막기 위해 로딩 중 버튼을 비활성화한다.
- 브라우저의 현재 날짜가 아닌 데이터의 실제 기준 시각을 별도 표시한다.

### OV-002. 긴급 알림 및 오늘의 핵심 신호

**목적:** 사용자가 가장 먼저 확인해야 할 변화를 최대 5건으로 압축한다.

**대상 신호**

- 24시간 내 중요 Filing 등록
- 매출 또는 EPS Beat/Miss 임계치 초과
- 목표주가 또는 컨센서스의 유의미한 변화
- 일간 주가 급변
- DRAM/NAND/GPU 가격 또는 한국 수출지표 급변
- 72시간 내 실적 발표
- 수집 실패 또는 데이터 지연

**표시 필드**

- 심각도: Critical, Warning, Info
- 신호 유형
- 기업 또는 산업지표
- 한 줄 설명
- 발생 시각 또는 기준일
- 관련 상세 화면 이동 링크

**기본 임계치**

| 신호 | 초기 임계치 |
|---|---:|
| 매출 서프라이즈 | 절대값 3% 이상 |
| EPS 서프라이즈 | 절대값 5% 이상 |
| 일간 주가 변화 | 절대값 5% 이상 |
| 목표주가 평균 변화 | 7일간 절대값 5% 이상 |
| 산업지표 변화 | 직전 관측 대비 절대값 5% 이상 |
| 데이터 지연 | 예정 주기 대비 1회 이상 미갱신 |

임계치는 향후 설정 파일로 이동할 수 있어야 한다.

### OV-003. 핵심 KPI 카드

기존 누적 건수 중심 KPI를 다음 4개 카드로 변경한다.

#### KPI 1: 다음 실적 발표

- 티커 및 기업명
- D-Day
- 회계 분기
- 발표 예정 시각
- 일정 상세 이동

#### KPI 2: 최근 24시간 신규 공시

- 신규 공시 건수
- 10-Q, 10-K, 8-K 등 유형별 요약
- 가장 최근 중요 공시 기업
- Filing 아카이브 이동

#### KPI 3: 최신 Beat/Miss

- 가장 최근 발표 기업
- BEAT, INLINE, MISS 상태
- 매출 및 EPS surprise 비율
- Beat/Miss 상세 이동

#### KPI 4: 데이터 신선도

- 정상 데이터 소스 수 / 전체 소스 수
- 가장 오래된 주요 데이터의 경과시간
- 수집 오류 건수
- 수집 콘솔 이동

**공통 요건**

- 값이 없으면 `데이터 없음`으로 표시한다.
- 이전 값과 비교 가능한 경우 증감 방향을 표시한다.
- 상태를 색상에만 의존하지 않고 텍스트 또는 아이콘으로 병기한다.

### OV-004. 향후 14일 어닝 레이더

**목적:** 다가오는 실적 이벤트를 우선순위에 따라 보여준다.

**표시 항목**

- D-Day
- 티커 및 기업명
- 레이어
- 회계 분기
- 발표 일시와 장전/장후 구분
- 일정 확정 여부
- 매출 컨센서스
- EPS 컨센서스
- 최근 컨센서스 방향
- `기업 상세`, `분기 실적` 이동 버튼

**정렬 규칙**

1. 발표일이 가까운 순서
2. 같은 날짜에는 확정 일정 우선
3. 같은 조건에는 레이어 순서 및 티커순

**범위 선택**

- 7일, 14일, 30일 선택
- 기본값 14일

### OV-005. 최신 실적 및 컨센서스 변화

**목적:** 최근 실적 결과와 시장 기대치의 차이를 한눈에 제공한다.

**표시 대상:** 최근 완료된 실적 발표 최대 6개사

**표시 항목**

- 기업 및 회계 분기
- 발표일
- 매출 Actual / Consensus / Surprise
- EPS Actual / Consensus / Surprise
- Beat/Miss 상태
- 발표 후 1일 및 5일 주가 수익률
- 데이터 출처

**시각화 규칙**

- BEAT: emerald 계열
- INLINE: neutral 또는 amber 계열
- MISS: rose 계열
- Forecast 및 Consensus에는 별도 라벨을 붙인다.
- 값의 통화와 단위를 생략하지 않는다.

### OV-006. 핵심 선행지표 스냅샷

**목적:** 밸류체인 실적을 선행할 수 있는 지표의 최근 방향성을 표시한다.

**기본 지표**

- 한국 반도체 10일 수출
- DRAM 현물가격
- NAND 현물가격
- GPU 임대가격
- TSMC 월매출
- 하이퍼스케일러 Capex

**카드별 표시 항목**

- 지표명
- 최신 값과 단위
- 기준일
- 직전 관측 대비 변화율
- 전년 동기 대비 변화율: 가능한 경우
- 최근 8~12개 관측치 미니 추세선
- 출처
- 갱신 상태

**동작 요건**

- 카드 클릭 시 선행지표 탭에서 해당 지표가 선택된 상태로 이동한다.
- 서로 다른 주기의 데이터를 동일 날짜로 오인하지 않도록 기준일을 명시한다.

### OV-007. 밸류체인 영향 맵

**목적:** 최신 신호가 어느 레이어와 기업에 연결되는지 보여준다.

**1차 구현 범위**

- 7개 운영 레이어별 기업 수
- 최근 7일 신규 이벤트 수
- 예정된 실적 발표 수
- 위험 또는 주목 신호 수
- 레이어별 대표 기업 최대 3개

**2차 확장 범위**

- Memory Claude 통합 후 계약, Capex, 캐파 및 공급 관계 반영
- 직접 영향과 간접 영향 구분
- 영향 방향: Positive, Negative, Mixed, Unknown
- 영향 시차와 신뢰도 표시

**동작 요건**

- 레이어 선택 시 해당 기업, 공시 및 신호만 필터링한 상세 화면으로 이동한다.
- 초기에는 복잡한 네트워크 그래프보다 읽기 쉬운 레이어 카드 또는 흐름형 UI를 사용한다.

### OV-008. 최근 중요 문서

기존 최근 Filing 표를 중요 문서 피드로 확장한다.

**포함 문서 유형**

- SEC Filing
- 어닝콜 트랜스크립트
- AI 요약 리포트
- 증권사 리포트
- 중요 산업지표 업데이트

**표시 필드**

- 중요도
- 문서 유형
- 기업
- 제목 또는 문서 형식
- 회계기간
- 등록일 또는 발표일
- 원문 보유 여부
- 요약 보유 여부
- 상세 동작

**정렬 규칙**

- 기본: 중요도 내림차순, 발생일 내림차순
- 사용자가 최신순으로 전환 가능

### OV-009. 데이터 품질 및 수집 상태

**표시 데이터 소스**

- SEC Filing
- 주가
- 실적 캘린더
- 컨센서스
- 어닝콜
- 한국 수출
- 메모리 가격
- GPU 가격
- 애널리스트 리포트

**소스별 표시 항목**

- 마지막 시도 시각

**동작 요건**

## 7. 데이터 및 API 요건

### 7.1 API 설계 원칙

- 초기 렌더링 요청 수를 줄이기 위해 개요 전용 집계 API를 제공한다.
- API 응답은 수치와 함께 `as_of`, `source`, `unit`, `status`를 포함한다.
- 서버에서 정렬과 임계치 판정을 수행하고 프런트엔드는 표시 책임에 집중한다.
- 일부 데이터 소스가 실패해도 전체 응답은 가능한 범위에서 반환한다.

### 7.2 신규 권장 API

#### `GET /api/overview`

개요 화면 최초 로딩에 필요한 통합 응답을 제공한다.

**Query parameters**

- `range`: `1d`, `7d`, `30d`; 기본값 `7d`
- `layer`: 선택값
- `ticker`: 선택값
- `earnings_window`: `7`, `14`, `30`; 기본값 `14`

**응답 예시**

```json
{
  "status": "success",
  "data": {
    "generated_at": "2026-10-08T09:30:00+09:00",
    "system_status": "PARTIAL_DELAY",
    "alerts": [],
    "kpis": {
      "next_earning": null,
      "new_filings_24h": 0,
      "latest_surprise": null,
      "data_freshness": null
    },
    "earnings_radar": [],
    "recent_results": [],
    "leading_indicators": [],
    "value_chain": [],
    "recent_documents": [],
    "source_health": []
  },
  "warnings": []
}
```

#### `GET /api/overview/alerts`

긴급 알림을 별도로 갱신할 때 사용한다.

#### `GET /api/overview/source-health`

수집 데이터의 신선도와 오류 상태를 제공한다.

### 7.3 기존 API 재사용

- `/api/stats`: 마이그레이션 기간 동안 유지
- `/api/filings`: 최근 공시 상세 조회
- `/api/calendar`: 전체 일정 상세 조회
- `/api/entities`: 기업 및 레이어 필터
- 기존 consensus, financial, indicator 관련 API: 상세 화면 이동 시 사용

### 7.4 추가 데이터 구조 권장

현재 DB에서 수집 성공·실패 이력을 통합 관리하기 어렵다면 다음 테이블을 추가한다.

```sql
CREATE TABLE collection_run (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    source_type TEXT NOT NULL,
    job_name TEXT NOT NULL,
    started_at TEXT NOT NULL,
    finished_at TEXT,
    status TEXT NOT NULL,
    records_inserted INTEGER DEFAULT 0,
    records_updated INTEGER DEFAULT 0,
    error_message TEXT,
    latest_data_date TEXT,
    created_at TEXT DEFAULT (datetime('now'))
);
```

필요 시 별도 `signal_event` 테이블을 도입한다.

```sql
CREATE TABLE signal_event (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    signal_type TEXT NOT NULL,
    severity TEXT NOT NULL,
    entity_id INTEGER,
    indicator_type TEXT,
    event_date TEXT NOT NULL,
    title TEXT NOT NULL,
    summary TEXT,
    current_value REAL,
    comparison_value REAL,
    change_pct REAL,
    source_type TEXT,
    source_id TEXT,
    status TEXT DEFAULT 'ACTIVE',
    created_at TEXT DEFAULT (datetime('now')),
    FOREIGN KEY (entity_id) REFERENCES entity(id) ON DELETE SET NULL
);
```

`signal_event`는 2차 구현 항목이며, 1차에서는 조회 시 동적 계산할 수 있다.

## 8. UI 및 디자인 요건

### 8.1 시각적 방향

- 기존 딥 네이비·차콜 다크 테마를 유지한다.
- 장식적인 글래스 효과보다 정보 계층과 가독성을 우선한다.
- 한 패널 안에 강조색을 과도하게 사용하지 않는다.
- 숫자는 tabular numeral을 적용해 비교하기 쉽게 한다.
- 본문 최소 글자 크기는 데스크톱 13px, 모바일 14px로 한다.

### 8.2 상태 색상

| 의미 | 권장 색상 | 보조 표현 |
|---|---|---|
| 정상·상승·Beat | Emerald | ↑, BEAT, 정상 |
| 주의·Inline·지연 | Amber | !, INLINE, 지연 |
| 위험·하락·Miss | Rose | ↓, MISS, 오류 |
| 정보·예정 | Cyan | i, 예정 |
| 미확인·데이터 없음 | Gray | —, 미확인 |

상승이 항상 긍정적이지 않은 지표가 있으므로, 방향 색상과 평가 색상을 구분해야 한다. 예를 들어 GPU 임대가격 상승은 공급 부족 신호일 수 있으므로 단순히 녹색으로 표시하지 않는다.

### 8.3 로딩·빈 상태·오류 상태

- 첫 로딩 시 레이아웃을 유지하는 skeleton UI를 표시한다.
- 패널별 오류를 독립적으로 처리한다.
- 빈 상태에는 원인과 다음 행동을 제시한다.
- 오류 메시지에 내부 stack trace나 민감한 경로를 노출하지 않는다.
- 재시도 버튼은 실패한 패널의 API만 다시 호출한다.

### 8.4 접근성

- 키보드만으로 모든 카드와 버튼에 접근할 수 있어야 한다.
- 포커스 상태를 명확히 표시한다.
- 색상만으로 상태를 전달하지 않는다.
- 아이콘에는 `aria-label` 또는 숨김 텍스트를 제공한다.
- 테이블 헤더와 데이터 셀의 연결을 유지한다.
- 차트에는 동일 데이터를 확인할 수 있는 텍스트 요약을 제공한다.

## 10. 비기능 요건

### 10.1 성능

- 로컬 환경 기준 개요 API 응답 목표: 500ms 이내
- 개요 화면 주요 콘텐츠 표시 목표: 1.5초 이내
- 차트 라이브러리 로딩 실패 시 텍스트 데이터는 계속 표시
- 개요 최초 로딩 API 호출 수: 최대 3회 권장
- DB 집계 쿼리에 필요한 인덱스를 추가하되 기존 데이터 적재 성능을 검증

### 10.2 안정성

- 한 데이터 소스의 오류가 전체 개요 화면을 중단시키지 않아야 한다.
- API 응답 필드가 `null`이어도 JavaScript 오류가 발생하지 않아야 한다.
- 날짜와 시간대는 API에서 명시하고 화면에서 Asia/Tokyo 기준으로 표시하되, ET 발표 시각은 원 시간대를 병기한다.

### 10.3 보안

- 원문 및 리포트 제목을 HTML로 삽입할 때 escape 처리한다.
- URL query parameter를 검증한다.
- 개요 새로고침은 데이터 조회만 수행하며 외부 수집을 자동 실행하지 않는다.
- 수집 실행은 기존 수집 콘솔의 명시적 사용자 동작으로 제한한다.

### 10.4 호환성

- 최신 Chrome, Safari, Edge 지원
- 별도 프런트엔드 빌드 도구를 도입하지 않음
- 기존 탭 ID와 상세 화면 기능을 유지

## 16. 향후 확장 방향

```text
관측 신호
```
