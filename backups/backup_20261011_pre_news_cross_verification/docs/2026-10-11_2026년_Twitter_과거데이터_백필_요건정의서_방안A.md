# 2026년 Twitter(𝕏) 과거 데이터 소급 수집(Backfill) 요건정의서 (방안 A)

**문서 버전**: v1.0  
**작성 일자**: 2026-10-11  
**관련 시스템**: `c_1006_subject_outline` (SignalForge), `b_0917_10_QK_EARNING` (SiliconPulse)  
**대상 기간**: 2026-01-01 ~ 2026-08-31 (8개월 소급 백필)

## 1. 배경 및 문제 정의

### 1.1 현황
* 현재 `b_0917_10_QK_EARNING`의 36개사 2026 연간 통합 원장(8열 Full Matrix)은 총 985건의 이벤트를 집계하고 있음.
* 이 중 트위터(𝕏) 시그널은 총 625건이나, 분석 결과 **모두 2026년 9월~10월(최근 1개월)에 집중**되어 있음.
* `c_1006_subject_outline/data/timeline.db`의 `timeline_events` 테이블 확인 결과:
  * `2025-09`: 1건
  * `2026-09`: 144건
  * `2026-10`: 1,065건
  * **2026-01 ~ 2026-08: 0건 (완전 부재)**

### 1.2 원인 분석
* `c_1006_subject_outline/src/collectors/twitter_fetcher.py`의 기본 수집 파라미터가 `since_hours=24.0`, `limit=5`로 설정된 **"최근 24시간 실시간 모니터링 데몬"**으로 설계되어 있었음.
* 따라서 프로젝트가 시작된 9월 중순 이전의 과거 타임라인은 수집 대상에 포함되지 않았음.

### 1.3 목표
* **방안 A(실제 𝕏 과거 데이터 백필 파이프라인)**를 적용하여, 반도체 밸류체인 36개사 핵심 인플루언서 계정들의 2026년 1월 1일 ~ 8월 31일 과거 트윗을 안전하게 소급 수집하고, `timeline.db`에 적재하여 2026년 연간 원장의 시간적 공백을 완벽히 해소한다.

## 3. 백필(Backfill) 아키텍처 및 구현 설계

```text
[Twitter/X]
    │
    ▼ (twscrape 비공식 API / accounts.db 세션 풀)
[scripts/backfill_2026_tweets.py]
    │
    ├─ 1) Since: 2026-01-01 / Until: 2026-08-31 날짜 필터링
    ├─ 2) Concurrency: 1~2 (계정 밴 방지 Pacing: 계정당 3~5초 대기)
    ├─ 3) Duplicate Check: tweet.id 기준 중복 방지
    ├─ 4) Link Enrichment: 트윗 내 링크 제목/요약 스크래핑
    │
    ▼ (SQLite INSERT OR IGNORE)
[c_1006_subject_outline/data/timeline.db]
    │
    ▼ (twitter_bridge.py / EntityMatcher & ConfidenceGrader)
[scripts/build_2026_full_year_matrix.py]
    │
    ▼ (Plan A 8열 연간 통합 원장 재빌드)
[docs/2026-10-11_36entities_2026_full_year_layer_matrix.md]
    │
    ▼ (REST API /api/ledger/2026)
[SiliconPulse Terminal 8열 매트릭스 UI]
```

## 4. 핵심 엔지니어링 제약 및 안전 수칙

1. **Anti-Ban Pacing Rule**:
   * 트위터 계정 섀도우밴을 피하기 위해 동시 요청(Concurrency)은 2 이하로 제한한다.
   * 각 계정 조회 간 최소 2.5초 ~ 4.0초의 랜덤 딜레이를 부여한다.
2. **Date Window Clamping**:
   * 각 트윗의 `created_at`이 `2026-01-01` 이전이거나 `2026-08-31` 이후인 경우 수집을 중단하거나 스킵한다.
3. **Idempotency (멱등성)**:
   * 이미 `timeline.db`에 존재하는 URL 또는 트윗 ID는 `INSERT OR IGNORE` 처리하여 중복 적재되지 않도록 한다.
4. **Read-Only 격리**:
   * `b_0917` 프로젝트는 오직 읽기 전용(`mode=ro`)으로만 `timeline.db`에 접근하며, 백필 쓰기는 `c_1006` 측 전용 백필 스크립트만 수행한다.
