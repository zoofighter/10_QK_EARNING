# QK_EARNING 회사별 통합 메뉴 및 Memory Claude 연계 화면 요건정의서

**문서 버전:** v1.0  
**작성일:** 2026-10-08  
**기준 프로젝트:** `b_0917_10_QK_EARNING`  
**연계 프로젝트:** `b_0910_memory_claude`  
**구현 대상:** QK_EARNING 웹 대시보드의 탐색 구조 및 회사별 상세 화면

---

## 1. 목적

현재 QK_EARNING의 기능별 메뉴 구조를 **회사 중심 탐색 구조**로 보완하고, 한 회사 화면 안에서 QK_EARNING의 공시·실적·주가·컨센서스 데이터와 Memory Claude의 계약·Capex·생산능력·데이터센터·기술 마일스톤 데이터를 함께 확인할 수 있도록 화면 요건을 정의한다.

사용자는 여러 기능 탭을 오가며 같은 회사를 반복해서 선택하지 않고 다음 질문에 답할 수 있어야 한다.

1. 이 회사의 최근 실적과 컨센서스는 어떻게 변했는가?
2. 최근 공시와 어닝콜에서 무엇이 달라졌는가?
3. 이 회사는 AI 밸류체인에서 어떤 역할을 하는가?
4. 주요 고객, 공급자, 계약 및 투자 관계는 무엇인가?
5. Capex, 팹, 패키징, 데이터센터 및 기술 로드맵은 어떻게 진행되는가?
6. 어떤 산업 선행지표가 이 회사에 영향을 주는가?
7. 표시된 분석의 근거와 신뢰도는 무엇인가?

---

## 2. 기본 방향

### 2.1 통합 기준

통합 화면은 QK_EARNING을 기본 애플리케이션으로 사용한다.

> **QK_EARNING:** 화면, API, 수집 파이프라인 및 운영 기반  
> **Memory Claude:** 밸류체인 관계, 계약, 캐파, 마일스톤 및 장기 분석 데이터

Memory Claude의 정적 대시보드를 그대로 삽입하지 않는다. Memory Claude 데이터를 회사별 API로 제공하고 QK_EARNING 디자인 체계에서 다시 표현한다.

### 2.2 핵심 UX 원칙

- 최상위 탐색축을 `기능`뿐 아니라 `회사`로 제공한다.
- 회사를 한 번 선택하면 회사별 하위 메뉴를 이동해도 선택 상태를 유지한다.
- 같은 수치가 두 시스템에 존재하면 출처와 검증 상태를 표시한다.
- 공시 원문과 분석 결과를 연결한다.
- Actual, Consensus, Guidance, Forecast를 명확히 구분한다.
- 모든 기업에 동일한 빈 화면을 강요하지 않고 기업 유형에 맞는 모듈을 노출한다.
- Memory Claude 데이터가 없는 회사도 QK 기본 화면은 정상 작동해야 한다.

## 3. 대상 정보 구조

### 3.1 글로벌 내비게이션

최상위 메뉴는 다음과 같이 재구성한다.

```text
개요
회사
실적·공시
시장·선행지표
밸류체인
리포트
수집·관리
```

기존 메뉴는 삭제하지 않고 관련 그룹 아래에 재배치한다.

| 신규 상위 메뉴 | 포함 기능 |
|---|---|
| 개요 | 데일리 인텔리전스, 중요 신호, 실적 일정 |
| 회사 | 회사 디렉터리, 회사별 통합 화면 |
| 실적·공시 | 공시, 분기 실적, 어닝콜, Beat/Miss, 어닝 캘린더 |
| 시장·선행지표 | 주가, 목표가, 증권사 리포트, 수출, 메모리 가격, GPU 가격 |
| 밸류체인 | 계약, 기업 관계, Capex, 팹, 데이터센터, 기술 마일스톤 |
| 리포트 | AI 리포트, 회사별 분석, 비교 리포트 |
| 수집·관리 | 수집 콘솔, 데이터 품질, 데이터 출처 |

### 3.2 회사 메뉴의 레이어 구조

회사는 7개 운영 레이어와 향후 추가될 L1을 기준으로 묶는다.

```text
회사
├── 전체 회사
├── L1 AI Frontier Lab            # Memory Claude 연계 후 표시
├── L2 하이퍼스케일러
│   ├── AMZN 아마존
│   ├── GOOGL 알파벳
│   ├── META 메타
│   ├── MSFT 마이크로소프트
│   └── ...
├── L3 컴퓨팅·가속기
│   ├── NVDA 엔비디아
│   ├── AMD
│   └── ...
├── L4 파운드리·장비·패키징
├── L5 메모리·스토리지
├── L6 광통신·네트워킹
├── L7 인프라·특수 플랫폼
└── L8 전력·에너지
```

### 3.3 회사 선택 UI

데스크톱에서는 다음 두 방식을 함께 제공한다.

- 상위 `회사` 메뉴 진입 후 레이어별 회사 디렉터리
- 좌측 회사 사이드바에서 빠른 회사 전환

모바일에서는 사이드바 대신 검색 가능한 회사 선택 드롭다운 또는 전체 화면 선택 패널을 사용한다.

회사 선택 UI는 다음 정보를 포함한다.

- 티커
- 회사명
- 레이어 배지
- 국가
- 관심기업 표시
- 중요 신호 개수
- 다음 실적 D-Day

## 4. 회사별 화면 구조

### 4.1 회사 URL

회사 상세는 modal이 아닌 독립적으로 접근 가능한 화면 상태를 가져야 한다.

권장 URL:

```text
/companies/NVDA
/companies/NVDA/earnings
/companies/NVDA/filings
/companies/NVDA/value-chain
```

현재 단일 HTML 구조를 유지하는 1차 단계에서는 hash 또는 query parameter를 사용할 수 있다.

```text
/?view=company&ticker=NVDA&section=overview
#/companies/NVDA/earnings
```

브라우저 새로고침과 링크 공유 후에도 동일한 회사와 하위 메뉴가 열려야 한다.

### 4.2 공통 회사 헤더

모든 회사 하위 메뉴 상단에 고정되는 헤더다.

**표시 항목**

- 회사명과 티커
- 거래소 및 국가
- 밸류체인 레이어
- 데이터 소스: SEC, DART, TSE, Manual 등
- 최근 종가와 일간 등락률
- 시가총액: 데이터가 있는 경우
- 다음 실적 발표일과 D-Day
- 최신 데이터 기준 시각
- 관심기업 등록 버튼
- 회사 전환 버튼

**상태 배지**

- Actual 데이터 최신 여부
- 수집 상태
- Memory Claude 연계 여부
- 데이터 신뢰도

### 4.3 회사별 하위 메뉴

```text
회사 개요
실적
공시
어닝콜
컨센서스·목표가
시장·선행지표
밸류체인
계약·투자
Capex·캐파
마일스톤
AI 분석
출처·품질
```

모든 회사에 모든 메뉴를 강제로 표시하지 않는다. 데이터 또는 기업 유형에 따라 비활성·숨김 규칙을 적용한다.

## 5. 회사별 메뉴 상세 요건

### CO-001. 회사 개요

회사의 현재 상태를 한 화면에서 요약한다.

**상단 KPI**

- 최근 분기 매출
- 전년 동기 대비 매출 성장률
- 영업이익률
- Capex
- 최신 Beat/Miss
- 다음 실적 D-Day

**핵심 패널**

1. 최근 8개 분기 매출·영업이익률 추이
2. 최근 실적 Actual 대 Consensus
3. 최근 중요 공시와 어닝콜
4. 회사 관련 중요 신호
5. 밸류체인 역할 및 주요 관계
6. 향후 마일스톤
7. 데이터 최신성 및 신뢰도

**동작**

- 각 KPI와 패널은 해당 하위 메뉴로 연결한다.
- 회사 유형에 맞는 핵심 KPI를 우선 배치한다.

예:

- 하이퍼스케일러: Capex, 데이터센터 전력, AI 인프라 투자
- 컴퓨팅: 데이터센터 매출, 가속기 로드맵, 파운드리·HBM 의존성
- 파운드리: 가동률, 첨단공정, 패키징 캐파
- 메모리: DRAM/HBM/NAND 지표, ASP, 재고, Capex
- 전력: 수주, 데이터센터 노출도, 전력 인프라 캐파

### CO-002. 실적

QK `financial_metric`과 Memory Claude `earnings_reports`를 회사·분기 기준으로 통합 표현한다.

**표시 범위**

- 분기별 매출
- 영업이익 및 영업이익률
- 순이익
- EPS
- Gross margin
- Capex
- 사업부별 매출: 존재하는 경우
- 다음 분기 가이던스

**비교 기능**

- QoQ
- YoY
- Actual 대 Consensus
- Actual 대 Guidance
- 동일 레이어 기업 비교

**데이터 구분**

| 유형 | 표시 라벨 |
|---|---|
| 확정 실적 | Actual |
| 시장 예상 | Consensus |
| 회사 제시 | Guidance |
| 시스템 추정 | Forecast |

Memory Claude의 기준에 따라 2026-Q3 이후 데이터는 확정 근거가 없는 한 Forecast로 처리한다.

### CO-003. 공시

**대상 데이터**

- 10-Q, 10-K, 8-K
- 20-F, 6-K
- DART 공시
- 기업 IR 문서

**기능**

- 문서 유형, 기간 및 날짜 필터
- 제목과 본문 검색
- 원문 보기
- 섹션별 보기
- 관련 추출 수치 보기
- AI 요약 연결
- 이전 공시와 변화 비교

**근거 연결**

재무 수치 또는 분석 문장을 선택하면 가능할 경우 원문 문서와 해당 섹션으로 이동한다.

### CO-004. 어닝콜

**표시 항목**

- 분기별 트랜스크립트
- 경영진 발언 요약
- Q&A 핵심 질문
- 주요 키워드와 빈도
- 긍정·부정·불확실 표현
- 전 분기 대비 표현 변화
- 관련 마일스톤과 가이던스

요약 결과에는 모델명, 생성 시각 및 원문 링크를 표시한다.

### CO-005. 컨센서스·목표가

**표시 항목**

- 매출·EPS 컨센서스
- Actual과 surprise 비율
- Beat/Inline/Miss 이력
- 실적 후 1일·5일 주가 반응
- 목표주가 평균, 최고, 최저
- 주요 증권사별 목표가
- 상향·하향 및 투자의견 변화

**차트**

- 주가와 평균 목표주가 시계열
- 실적 발표일 표시
- 목표가 변경 이벤트 표시

### CO-006. 시장·선행지표

회사별로 관련성이 높은 지표를 자동 연결한다.

| 레이어/기업 유형 | 기본 연결 지표 |
|---|---|
| 하이퍼스케일러 | Capex, GPU 임대가격, 데이터센터 전력 |
| 컴퓨팅 | GPU 가격, TSMC 월매출, HBM 가격·수출 |
| 파운드리·장비 | TSMC 월매출, 장비 매출, 첨단 패키징 캐파 |
| 메모리 | DRAM/NAND 가격, 한국 수출, HBM 수급 |
| 네트워킹 | 데이터센터 Capex, 광트랜시버 수요 |
| 전력 | 데이터센터 전력, PPA, 전력설비 수주 |

**표시 항목**

- 지표명
- 최신 값과 단위
- 기준일
- 최근 변화율
- 회사와의 관계 설명
- 관련성 유형: 직접, 간접, 참고
- 출처와 신뢰도

상관관계를 인과관계로 표현하지 않는다.

### CO-007. 밸류체인

Memory Claude의 관계 데이터를 회사 중심으로 보여준다.

**구성**

- 회사의 밸류체인 역할 설명
- 주요 고객
- 주요 공급자
- 파트너 및 투자 관계
- 관련 제품 및 기술
- 상·하류 레이어 연결

**1차 표현**

- 읽기 쉬운 관계 카드와 표
- 관계 방향: Buyer → Seller
- 관계 유형: Supply, Investment, Partnership, License, Service

**2차 표현**

- 회사 중심 1-hop 네트워크 그래프
- 사용자가 요청할 때만 2-hop 확장
- 관계선 클릭 시 계약과 근거 표시

그래프만으로 정보를 전달하지 않고 동일 내용을 표로도 제공한다.

### CO-008. 계약·투자

Memory Claude `contracts` 데이터를 회사별로 조회한다.

**표시 항목**

- 구매자와 판매자
- 계약 유형
- 제품 또는 서비스
- 계약 규모와 통화
- 발표일
- 시작일과 종료일
- 계약 설명
- 신뢰도
- 출처 및 원문

**필터**

- 구매 계약 / 판매 계약
- 계약 유형
- 기간
- 확정 수준

계약 규모가 공개되지 않은 경우 값을 추정해 채우지 않고 `비공개`로 표시한다.

### CO-009. Capex·캐파

기업 유형에 따라 관련 모듈을 조건부로 표시한다.

**공통 Capex**

- 연간·분기 Capex
- 매출 대비 Capex 비율
- 전년 대비 증감
- 가이던스 및 Forecast 구분

**Fab·패키징 기업**

- 팹 명칭과 위치
- 공정 노드
- 현재 및 목표 WSPM
- Ramp 일정
- 가동률 및 수율: 존재하는 경우
- 투자 규모
- 주요 고객

**하이퍼스케일러·인프라 기업**

- 데이터센터 명칭과 위치
- 현재 및 목표 전력 MW
- 전력원
- 냉각 방식
- 목표 가속기 수량
- 주력 칩
- 가동 예정 시기
- 투자 규모

**메모리 기업**

- HBM/DRAM/NAND 라인
- 현재 및 목표 캐파
- 양산 시기
- 관련 고객과 제품 세대

단위가 다른 캐파를 하나의 합계로 단순 합산하지 않는다.

### CO-010. 마일스톤

Memory Claude `milestones`를 회사 타임라인으로 표현한다.

**범주**

- Earnings
- Product Launch
- Fab Milestone
- Regulation
- Partnership
- Restructuring
- Scenario Signal
- Price

**표시 항목**

- 날짜 또는 예상 기간
- 이벤트 설명
- 영향 수준
- Actual/Forecast
- 신뢰도
- 출처

과거 이벤트와 향후 이벤트를 시각적으로 분리한다.

### CO-011. AI 분석

QK의 `llm_summary`와 Memory Claude의 정량·정성 분석을 함께 제공한다.

**섹션**

- 최근 분기 핵심 요약
- 전 분기 대비 변화
- Bull / Base / Bear 논점
- 실적 체크포인트
- 밸류체인 파급효과
- 확인이 필요한 데이터 공백

**필수 표시**

- 분석 생성 시각
- 사용 모델
- 대상 데이터 기준일
- 근거 문서 링크
- 사실과 해석 구분

LLM 결과를 확정 사실처럼 표시하지 않는다. 근거가 없는 경우 `검증 필요`로 표시한다.

### CO-012. 출처·품질

회사 화면에서 사용된 데이터의 신뢰성과 계보를 확인한다.

**표시 항목**

- 데이터 항목
- 원본 출처
- 원본 통화 및 단위
- 정규화 통화 및 단위
- 환율 및 환산 기준
- 수집 시각
- 검증 시각
- 신뢰도
- 정정 이력
- QK/Memory Claude 출처 구분

동일 회사·분기·지표에 값이 둘 이상이면 불일치 상태와 우선 적용 값을 표시한다.

## 7. Memory Claude 데이터 연계 요건

### 7.1 엔티티 매핑

QK의 숫자형 `entity.id`와 Memory Claude의 의미형 `entity_id`를 직접 동일시하지 않는다.

권장 매핑 테이블:

```sql
CREATE TABLE entity_source_map (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    entity_id INTEGER NOT NULL,
    source_system TEXT NOT NULL,
    source_entity_id TEXT NOT NULL,
    source_ticker TEXT,
    match_method TEXT NOT NULL,
    match_status TEXT NOT NULL DEFAULT 'VERIFIED',
    valid_from TEXT,
    valid_to TEXT,
    created_at TEXT DEFAULT (datetime('now')),
    FOREIGN KEY (entity_id) REFERENCES entity(id),
    UNIQUE (source_system, source_entity_id)
);
```

예:

```text
QK entity.id: 12
QK ticker: NVDA
Memory entity_id: NVIDIA
canonical display ticker: NVDA
```

티커만으로 자동 매핑하지 않는다. 한국·일본 종목의 접미사, ADR, 복수상장 및 티커 변경을 고려한다.

### 7.2 1차 연계 방식

초기에는 두 DB를 물리적으로 병합하지 않고 QK 애플리케이션에서 Memory Claude DB를 읽기 전용으로 연결한다.

권장 방식:

1. 별도 `MemoryClaudeRepository` 구현
2. 읽기 전용 SQLite URI 사용
3. entity mapping을 통한 조회
4. QK API에서 통합 응답 생성
5. 화면은 데이터 출처를 구분하지 않고 사용하되 상세 출처에서 확인 가능

### 7.3 중기 연계 방식

검증된 데이터만 QK의 통합 분석 계층으로 동기화한다.

```text
Memory Claude 원본 테이블
 → 매핑·검증
 → 통합 분석 테이블
 → 회사별 API
 → 회사별 화면
```

### 7.4 데이터 소유권

| 데이터 | 기준 소유 시스템 |
|---|---|
| Filing 및 원문 | QK_EARNING |
| 어닝콜 | QK_EARNING |
| 주가 | QK_EARNING |
| 컨센서스·목표가 | QK_EARNING |
| 원자적 재무지표 | QK_EARNING |
| 검증된 분기 분석 마트 | 공동 |
| 계약 | Memory Claude |
| 팹·패키징 캐파 | Memory Claude |
| 데이터센터 캐파 | Memory Claude |
| 기술 마일스톤 | Memory Claude |
| 기업 관계 | Memory Claude |
| AI 분석 결과 | 생성 위치 및 버전 명시 |

### 7.5 충돌 처리

동일 지표가 두 시스템에 존재할 때 다음 순서로 처리한다.

1. 공식 공시 또는 공식 IR 원문에 연결된 검증값
2. 검증 완료된 수기 정정값
3. 자동 추출값
4. 제3자 데이터
5. LLM 추정값

자동으로 기존 값을 덮어쓰지 않는다. 불일치는 별도 검증 대상으로 기록한다.

## 10. 상태 및 예외 처리

### 10.1 회사가 존재하지 않는 경우

- 404 상태와 함께 회사 검색을 제공한다.
- 유사 티커 또는 회사명이 있으면 제안한다.

### 10.2 Memory Claude 매핑이 없는 경우

- QK 기본 회사 화면은 정상 표시한다.
- Memory 전용 메뉴는 숨기거나 `연계 데이터 없음`으로 표시한다.
- 매핑되지 않았다는 사실을 오류가 아닌 데이터 상태로 처리한다.

### 10.3 일부 데이터만 있는 경우

- 사용 가능한 섹션을 먼저 표시한다.
- 빈 차트 영역을 그대로 남기지 않는다.
- 데이터가 없는 이유와 수집 또는 검증 방법을 안내한다.

### 10.4 비상장 기업

- 주가, 목표가 및 Beat/Miss 메뉴를 숨긴다.
- 계약, 투자, 데이터센터, 마일스톤을 우선 노출한다.

### 10.5 출처 간 수치 불일치

- 화면에는 우선값과 `불일치` 배지를 표시한다.
- 출처·품질 메뉴에서 두 값을 비교한다.
- 사용자 검증 전 자동 병합하거나 평균내지 않는다.

### 11.1 성능

- 문서 제목, AI 요약 및 원문 발췌를 HTML escape한다.

- 회사 화면 조회만으로 외부 수집이나 DB 갱신을 시작하지 않는다.

## 14. 인수 조건

다음 조건을 모두 만족하면 회사별 통합 화면 1차 구현이 완료된 것으로 판단한다.

1. 사용자가 레이어별 회사 목록에서 회사를 선택할 수 있다.
2. 회사 선택 후 하위 메뉴를 이동해도 회사가 유지된다.
3. URL 복사와 새로고침 후 동일 회사와 메뉴가 열린다.
4. 회사 개요에서 최근 실적, 다음 일정, 중요 문서 및 핵심 신호를 확인할 수 있다.
5. 실적, 공시, 어닝콜 및 컨센서스 메뉴가 기존 QK 데이터와 연결된다.
6. Memory 연계 회사에서 관계, 계약, 캐파 및 마일스톤을 확인할 수 있다.
7. Memory 미연계 회사도 QK 기본 화면은 오류 없이 동작한다.
8. Actual, Consensus, Guidance 및 Forecast가 구분된다.
9. 모든 주요 수치에 단위, 기준일 및 출처가 표시된다.
10. 동일 지표의 값이 충돌하면 불일치가 표시되고 자동 덮어쓰지 않는다.
11. 비상장 기업에는 부적절한 주가·목표가 메뉴가 노출되지 않는다.
12. 모바일 375px에서 회사 선택과 주요 메뉴를 사용할 수 있다.
13. 회사 화면 조회로 외부 데이터 수집이나 DB 쓰기가 실행되지 않는다.
14. 기존 QK 상세 탭과 API에 회귀 오류가 없다.

- `VRT`: 전력·냉각 인프라 및 데이터센터 관계
- `SPACEX`: 비상장 기업의 계약·투자·마일스톤 중심 화면

## 17. 최종 화면 정의

회사별 통합 화면은 단순한 기업 프로필이 아니다.

```text
회사 선택
 → 최신 실적과 시장 기대 확인
 → 공시·어닝콜 근거 검토
 → 계약·공급 관계 확인
 → Capex·캐파·기술 일정 확인
 → 관련 선행지표 연결
 → 밸류체인 영향과 향후 체크포인트 도출
```

최종적으로 사용자는 한 회사 화면에서 다음 질문에 답할 수 있어야 한다.

> **이 회사의 실적을 움직이는 수요·공급·투자 요인은 무엇이며, 그 변화가 밸류체인의 어디에서 관측되고 있는가?**

## 18. 추가 설계 제안 요소

본 절은 회사별 통합 화면을 단순 데이터 조회 화면에서 **회사별 투자 가설과 밸류체인 변화를 추적하는 작업공간**으로 발전시키기 위한 추가 요건을 정의한다.

### AD-001. 확장 가능한 회사 탐색 구조

34개 회사를 글로벌 상단 메뉴에 직접 나열하지 않는다. 회사 탐색 메뉴는 다음 순서로 구성한다.

```text
회사
├── 관심기업
├── 최근 본 기업
├── 중요 신호 발생 기업
├── 레이어별 기업
└── 전체 기업 검색
```

**추가 요건**

- 데스크톱에서는 접을 수 있는 좌측 회사 사이드바를 제공한다.
- 모바일에서는 검색 가능한 회사 선택 패널을 제공한다.
- 최근 본 기업은 브라우저 `localStorage`에 최대 10개까지 저장할 수 있다.
- 중요 신호 발생 기업은 활성 경보 수와 가장 높은 심각도를 표시한다.
- 기업 수가 증가해도 탐색 구조를 변경하지 않고 확장할 수 있어야 한다.

### AD-002. 회사 유형별 화면 템플릿

모든 기업에 동일한 KPI와 카드 구성을 적용하지 않는다. 공통 회사 화면 골격은 유지하되 기업 유형에 따라 KPI, 메뉴 순서 및 기본 패널을 다르게 제공한다.

| 기업 유형 | 우선 표시 항목 |
|---|---|
| 하이퍼스케일러 | AI Capex, 데이터센터 전력, GPU 배치, 클라우드 성장률 |
| AI 컴퓨팅 | 데이터센터 매출, 제품 로드맵, 파운드리·HBM 의존성 |
| 파운드리·장비 | 첨단공정, WSPM, 패키징 캐파, 가동률, 수주 |
| 메모리·스토리지 | HBM 세대, ASP, 재고, 캐파, 수출지표 |
| 광통신·네트워킹 | 데이터센터 매출, 포트 속도, 광모듈 및 스위치 수요 |
| 전력·냉각 | 수주잔고, 데이터센터 노출도, 전력·냉각 생산능력 |
| 비상장 기업 | 투자, 계약, 데이터센터, 기술 마일스톤 |

템플릿 선택은 `layer_code`만으로 결정하지 않고 필요 시 `company_archetype`을 별도로 관리한다.

### AD-003. 회사별 핵심 투자 가설

회사 개요 화면에 현재 핵심 투자 가설을 추적하는 전용 패널을 제공한다.

**표시 항목**

- 핵심 가설 제목
- 가설 설명
- 지지하는 신호
- 가설을 훼손하는 위험 신호
- 다음 확인 이벤트
- 상태: 강화, 유지, 약화, 폐기
- 최초 작성일과 마지막 검토일
- 작성자 또는 생성 방식
- 근거 문서

**예시**

```text
NVDA 핵심 가설
Blackwell 공급 정상화와 하이퍼스케일러 Capex 확대로
2027년까지 데이터센터 매출 성장이 유지된다.

지지 신호
- TSMC CoWoS 캐파 확대
- HBM 공급 증가
- MSFT·META Capex 상향

위험 신호
- GPU 임대가격 하락
- 고객 자체 ASIC 확대
- 중국 수출 규제
```

가설은 확정 사실과 구분하고 상태 변경 이력을 보존한다. LLM이 가설을 제안할 수는 있지만 사용자 또는 검증 절차 없이 확정 가설로 승격하지 않는다.

### AD-004. 이벤트 영향 경로

공시, 실적 또는 선행지표 이벤트가 다른 기업과 레이어로 전파되는 경로를 표시한다.

```text
MSFT Capex 상향
 → NVIDIA GPU 수요
 → TSMC 첨단 패키징
 → SK하이닉스 HBM
 → Vertiv 전력·냉각 수요
```

**관계별 메타데이터**

- 시작 기업 또는 지표
- 영향받는 기업
- 직접 또는 간접 영향
- 긍정, 부정, 혼합 또는 미확인
- 예상 시차
- 영향 강도
- 신뢰도
- 근거 문서
- 검증 상태

초기에는 검증된 관계를 수동 관리하고, 자동 추론 결과는 `제안` 상태로 분리한다.

### AD-005. 회사 비교

최소 2개, 최대 5개 기업을 동시에 비교할 수 있는 화면을 제공한다.

**기본 비교 그룹 예시**

- NVIDIA vs AMD
- TSMC vs Samsung Foundry
- SK하이닉스 vs 삼성전자 vs Micron
- ASML vs Applied Materials vs Lam Research vs KLA
- Microsoft vs Amazon vs Alphabet vs Meta
- Vertiv vs Eaton vs Schneider Electric

**비교 항목**

- 매출 및 성장률
- 영업이익률
- Capex와 매출 대비 Capex
- Actual 대 Consensus
- 주가 및 목표가
- 계약·캐파·마일스톤
- 데이터 신뢰도와 최신성

비교 전 회계기간, 통화 및 단위를 정규화한다. 비교 가능한 정의가 없는 값은 공란 또는 비교 불가로 표시하고 단순 합산하지 않는다.

### AD-006. 회계기간 정규화

기업마다 다른 회계연도를 안전하게 비교하기 위해 다음 필드를 구분한다.

```text
fiscal_year
fiscal_quarter
period_start_date
period_end_date
report_date
calendar_year
calendar_quarter
```

화면에는 `FY2026 Q2 · 기간 종료 2026-06-28`과 같이 표시한다. `2026-Q2` 문자열만으로 서로 다른 기업의 동일 기간을 판단하지 않는다.

### AD-007. 표준 지표 사전

QK의 `financial_metric.metric_type`과 Memory Claude의 컬럼을 일관된 의미로 연결하기 위해 표준 지표 사전을 구축한다.

권장 테이블:

```sql
CREATE TABLE metric_definition (
    metric_code TEXT PRIMARY KEY,
    name_ko TEXT NOT NULL,
    name_en TEXT NOT NULL,
    category TEXT NOT NULL,
    default_unit TEXT,
    value_type TEXT NOT NULL,
    direction_semantics TEXT,
    company_archetype TEXT,
    calculation_formula TEXT,
    validation_rule TEXT,
    created_at TEXT DEFAULT (datetime('now')),
    updated_at TEXT DEFAULT (datetime('now'))
);
```

다음처럼 같은 의미의 다양한 명칭을 표준 코드로 매핑한다.

```text
revenue
sales
net_sales
total_revenue
 → REVENUE
```

지표 사전에는 기본 단위, 계산식, 허용 범위, 방향성 및 원문 태그 매핑을 포함한다.

### AD-008. 숫자 단위의 데이터 계보 패널

주요 수치와 차트 데이터 포인트를 선택하면 출처와 정규화 이력을 확인할 수 있어야 한다.

```text
표시값: $30.04B
원래 값: NT$984.4B
적용 환율: 32.77 TWD/USD
환율 기준: 분기 평균
출처: TSMC 2026-Q2 6-K
추출 방식: 자동 추출 후 검증
검증일: 2026-09-16
```

출처·품질 메뉴로 이동하지 않아도 주요 KPI 카드에서 간단한 계보 정보를 바로 열 수 있게 한다.

### AD-009. 시간 정보 분리

선행지표 분석과 백테스트의 선견편향을 방지하기 위해 사실 발생 시점과 시스템 인지 시점을 분리한다.

```text
effective_at   # 실제 효력이 발생하거나 대상 기간이 끝난 시각
published_at   # 외부에 발표된 시각
collected_at   # 시스템에 수집된 시각
verified_at    # 검증이 완료된 시각
```

분석과 백테스트에서는 원칙적으로 `published_at` 또는 `collected_at` 이전에 해당 정보를 사용할 수 없다.

### AD-010. 통합 검색과 명령 팔레트

`Cmd/Ctrl + K`로 호출하는 통합 검색 및 이동 기능을 제공한다.

**검색 대상**

- 티커와 회사명
- 공시 및 어닝콜
- 계약
- 팹과 데이터센터
- 마일스톤
- 제품과 기술 키워드
- 지표

**검색 예시**

```text
NVDA
SK하이닉스 2026-Q2
CoWoS
HBM4
MSFT 계약
최근 8-K
```

검색 결과는 회사, 문서, 이벤트, 지표 등 유형별로 구분한다.

### AD-011. 데이터 검토함과 변경 이력

자동 수집 결과를 곧바로 확정값으로 반영하지 않고 검토 상태를 관리한다.

```text
수집
 → 자동 추출
 → 검증 대기
 → 승인
 → 분석 화면 반영
 → 정정 이력 보존
```

**검토 우선 대상**

- 기존 값과 임계치 이상 차이가 나는 수치
- QK와 Memory Claude의 불일치
- 단위 또는 환율이 불확실한 값
- 같은 회사·분기의 중복 데이터
- Forecast가 Actual 영역에 입력된 경우
- 출처 원문이 없는 수치

검토함에는 이전 값, 신규 값, 차이, 출처, 추천 조치 및 승인 이력을 표시한다.

### AD-012. 추가 제안의 구현 우선순위

#### 추가 P0 — 화면 기반

- 확장 가능한 회사 탐색
- 회사 유형별 화면 템플릿
- 표준 회계기간 표시

#### 추가 P1 — 분석 기반

- 핵심 투자 가설
- 표준 지표 사전
- 데이터 검토함과 변경 이력
- 회사 비교

#### 추가 P2 — 차별화 기능

- 이벤트 영향 경로
- 회사별 선행지표 자동 연결
- 통합 검색 및 명령 팔레트
- 가설 상태 변경 이력

#### 추가 P3 — 고도화

- Bull, Base, Bear 시나리오
- 선행지표 시차 분석
- 관계 기반 실적 영향 추정
- 검증된 근거를 사용하는 회사별 AI 질의응답

### AD-013. 추가 인수 조건

1. 회사 수가 증가해도 상단 메뉴가 과밀해지지 않는다.
2. 회사 유형에 따라 유효한 KPI와 메뉴가 우선 노출된다.
3. 핵심 투자 가설에서 사실, 해석 및 위험을 구분할 수 있다.
4. 회사 비교 시 회계기간, 통화 및 단위가 정규화된다.
5. 주요 수치에서 원본 출처와 환산 이력을 확인할 수 있다.
6. 이벤트 영향 관계에 방향, 시차, 강도 및 신뢰도가 표시된다.
7. 백테스트가 정보의 발표·수집 시점 이전 데이터를 사용하지 않는다.
8. 자동 추출값과 시스템 간 불일치를 검토함에서 확인할 수 있다.
9. 통합 검색에서 회사, 문서, 계약, 마일스톤 및 지표를 구분해 찾을 수 있다.
10. 검증되지 않은 자동 추론과 LLM 결과가 확정 사실로 표시되지 않는다.
