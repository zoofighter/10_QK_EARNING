* 어닝 캘린더 화면(`http://127.0.0.1:5001/#calendar`) 및 기업 허브 사이드바에서 **알파벳(구글), 아마존, 메타**의 2026년 3분기(Q3) 실적 발표일이 각각 `2026-10-01`, `2026-10-06`, `2026-10-08`로 표기되어 있었습니다.

## 2. 불일치 원인 분석 (Root Cause Analysis)

### 2.1 결산 주기 vs Mock 날짜 괴리
미국 상장 기업의 일반적인 회계 분기 마감 및 실적 공시 프로세스는 다음과 같습니다:
* **3분기(Q3) 회계 마감일**: 9월 30일
* **실적 공시 및 실적발표회**: 10월 말 ~ 11월 중순 (마감 후 통상 3~4주의 결산 및 외부 감사 검토 소요)

그러나 기존 시스템에는 UI 컴포넌트 렌더링 확인을 위해 10월 초 임의 날짜가 시드 데이터로 주입되어 있었습니다:
```python
# 기존 scripts/seed_entities.py의 결함 데이터
CALENDAR_SEEDS = [
    ("GOOGL", "2026", "Q3", "2026-10-01", "16:30", "COMPLETED"),  # 실제 불가능 (마감 후 1일 만에 발표 불가)
    ("AMZN", "2026", "Q3", "2026-10-06", "17:30", "COMPLETED"),   # 실제 불가능
    ("META", "2026", "Q3", "2026-10-08", "17:00", "UPCOMING"),    # 실제 불가능
    ("MSFT", "2027", "Q1", "2026-10-15", "17:30", "UPCOMING"),
]
```

이로 인해 기준일(2026-10-09) 시점에:
* **GOOGL**: 10월 1일이 지나 `COMPLETED (D+8)`로 강제 전이
* **AMZN**: 10월 6일이 지나 `COMPLETED (D+3)`로 강제 전이
* **META**: 어제(10월 8일) 일정이 되어 직전 상태로 왜곡

## 3. 해결 아키텍처 및 구현 명세

### 3.1 어닝 캘린더 수집기 (`EarningsCalendarCollector`)
* 파일 경로: [app/services/earnings_calendar_collector.py](file:///Users/boon/Dropbox/03_code/b_0917_10_QK_EARNING/app/services/earnings_calendar_collector.py)
* 주요 기능:
  1. `yfinance.Ticker(ticker).calendar`를 통해 금융시장에 공표된 `Earnings Date` 배열 추출.
  2. 기업별 비표준 회계연도 종료월(`fiscal_year_end`)을 반영하여 발표 분기 자동 매핑:
     * `06월 종료` (MSFT, LRCX, KLAC, WDC): 10월 발표 시 `Next FY Q1`
     * `09월 종료` (AAPL): 10월/11월 발표 시 `Current FY Q4`
     * `05월 종료` (ORCL): 9월 `Q1`, 12월 `Q2`
     * `10월 종료` (AVGO): 12월 `Q4`
     * `12월 종료` (GOOGL, AMZN, META, TSM 등): 10월 `Q3`, 1월/2월 `Q4`
  3. 컨퍼런스콜 시작 시각(ET) 표준화 (미국 빅테크 17:00 ET, 아시아/유럽 09:00 KST/CET).
  4. 당일 기준 D-Day 계산 및 상태 산출:
     * `D-0 ~ D-30`: `CONFIRMED`
     * `D > 30`: `UPCOMING`
     * `D < 0`: `COMPLETED`
  5. SQLite `earning_calendar` 테이블에 `ON CONFLICT(entity_id, fiscal_year, fiscal_quarter) DO UPDATE`로 안전한 UPSERT 처리.

### 3.2 데이터베이스 스키마 및 제약 조건
```sql
CREATE TABLE earning_calendar (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    entity_id INTEGER NOT NULL,
    fiscal_year TEXT NOT NULL,
    fiscal_quarter TEXT NOT NULL,
    expected_date TEXT NOT NULL,
    actual_date TEXT,
    call_time_et TEXT,
    status TEXT DEFAULT 'UPCOMING', -- UPCOMING, CONFIRMED, COMPLETED, POSTPONED
    created_at TEXT DEFAULT (datetime('now')),
    FOREIGN KEY (entity_id) REFERENCES entity(id) ON DELETE CASCADE,
    UNIQUE (entity_id, fiscal_year, fiscal_quarter)
);
CREATE INDEX idx_calendar_expected ON earning_calendar(expected_date ASC);
```

## 5. API 및 상시 유지보수 체계

### 5.1 REST API 엔드포인트 명세
* **`GET /api/calendar`**:
  * 전체 기업 실적 발표 일정 반환 (정렬: `expected_date ASC`).
  * 서버에서 실시간 `days_left` 및 `d_day`('D-20', 'D-Day', 'D+29') 자동 산출 제공.
  * 소속 레이어 한글명(`layer_name_ko`) 조인 제공.
* **`POST /api/calendar/sync`**:
  * 실시간 온디맨드 캘린더 동기화 트리거.
  * Body: `{"ticker": "GOOGL"}` (특정 티커만 갱신) 또는 `{}` (전체 34개사 일괄 갱신).
