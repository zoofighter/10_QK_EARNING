# LLM 기반 회사별 위키 구축 방안

## 1. 목적

SEC 공시, 실적 데이터, 뉴스 및 가치사슬 정보를 회사별로 축적하고, LLM이 근거를 바탕으로 위키 초안과 변경 제안을 작성하도록 한다. 위키는 단순 자동 생성 문서가 아니라 **근거 추적, 사용자 승인, 버전 관리**가 가능한 지식베이스로 운영한다.

## 2. 위키 콘텐츠 구성

회사별 페이지는 다음 내용을 포함한다.

- 회사 개요와 AI 반도체 가치사슬 내 역할
- 주요 제품과 사업부
- 주요 고객, 공급업체 및 경쟁사
- 분기별 실적과 핵심 KPI
- 경영진 발언 및 가이던스 변화
- CAPEX, 재고, 마진 및 수요 동향
- 성장 동력과 위험 요인
- 주요 사건 타임라인
- SEC 공시 원문 근거와 출처 링크
- 최신 변경 이력
- 해당 회사 자료 기반 AI 질의응답

## 3. 페이지 구조 예시

NVIDIA 위키 페이지 예시는 다음과 같다.

```text
NVIDIA
├── 한눈에 보기
├── AI 가치사슬 포지션
├── 주요 제품과 플랫폼
├── 고객·공급망 관계
├── 최근 실적 요약
├── 분기별 변화
├── 경영진 핵심 발언
├── 성장 동력
├── 위험 요인
├── 주요 사건 타임라인
└── 출처 및 SEC 원문
```

## 4. 생성 및 갱신 방식

### 4.1 자동 생성형

- DB와 SEC 공시를 기반으로 전체 페이지를 정기적으로 다시 생성
- 최신 내용 반영이 단순하고 빠름
- 기존 설명과 사용자 편집 내용이 덮어써질 위험이 있음
- 변경 이유를 추적하기 어려움

### 4.2 누적 갱신형 — 권장

- 기존 위키를 유지하고 새 문서에서 확인된 변경만 제안
- 문장 또는 사실마다 출처, 공시일, 신뢰도를 기록
- 확인된 사실, LLM 해석, 사용자 메모를 구분
- 사용자가 승인한 변경만 공식 위키에 반영
- 변경 전후의 수정 이력을 보존

## 5. 권장 데이터 모델

### `wiki_pages`

회사별 위키 페이지의 상태와 메타데이터를 저장한다.

- `id`
- `entity_id`
- `title`
- `status`
- `updated_at`

### `wiki_sections`

페이지의 섹션별 현재 콘텐츠를 저장한다.

- `id`
- `page_id`
- `section_key`
- `heading`
- `content`
- `display_order`

### `wiki_facts`

구조화된 사실과 수치를 저장한다.

- `id`
- `entity_id`
- `fact_type`
- `value`
- `unit`
- `period`
- `confidence`
- `source_id`

### `wiki_sources`

SEC 문서와 원문 위치를 저장한다.

- `id`
- `filing_id`
- `document_type`
- `filed_at`
- `source_url`
- `section_name`
- `text_offset`
- `source_excerpt`

### `wiki_revisions`

수정 전후 내용과 승인 상태를 저장한다.

- `id`
- `page_id`
- `section_id`
- `previous_content`
- `proposed_content`
- `change_reason`
- `status`
- `created_by`
- `created_at`
- `reviewed_at`

### `wiki_relations`

고객, 공급업체, 경쟁사 및 기술 관계를 저장한다.

- `id`
- `source_entity_id`
- `target_entity_id`
- `relation_type`
- `description`
- `confidence`
- `source_id`

## 6. LLM 작성 원칙

LLM이 자유롭게 지식을 생성하는 대신, 수집된 문서를 검색한 후 근거가 확인된 내용만 위키에 제안하도록 한다.

- 모든 사실 문장에 하나 이상의 출처 연결
- 직접 확인된 사실과 AI 해석을 시각적으로 구분
- 추론은 별도의 `AI 해석` 영역에 표시
- 근거가 충돌할 경우 최신 자료를 우선하되 충돌 사실을 표시
- 숫자와 날짜는 원문 값과 정규화 값을 함께 보존
- 출처가 삭제되거나 변경되어도 기존 스냅샷과 수정 이력 유지

## 7. 사용자 승인 흐름

```text
새 공시 수집
  → 원문 정제 및 문단 분할
  → 기존 위키와 비교
  → LLM 변경 제안 생성
  → 근거 및 신뢰도 검토
  → 사용자 승인·수정·거절
  → 공식 위키 반영
  → 수정 이력 저장
```

## 8. 권장 MVP

- 회사별 `/company/<ticker>/wiki` 화면
- 저장된 SEC 공시를 기반으로 위키 초안 생성
- 한눈에 보기, 최근 실적, 성장 동력, 위험 요인 섹션 제공
- 섹션별 재생성 및 사용자 직접 편집
- 문장 또는 항목별 공시 출처 표시
- 새 공시 수집 시 변경 제안 자동 생성
- 사용자가 승인한 변경만 공식 위키에 반영
- 수정 이력 조회 및 이전 버전 비교

## 9. 구현 단계

1. 공시 원문 저장과 정제 기능 완성
2. 원문을 문단 단위로 분할하고 FTS5 검색 인덱스 구성
3. 위키 페이지, 섹션, 출처 및 수정 이력 테이블 추가
4. 회사별 기본 위키 템플릿과 조회 API 구현
5. 검색된 근거만 사용하는 LLM 초안 생성 기능 구현
6. 변경 제안 승인·수정·거절 UI 구현
7. 회사별 질의응답과 관계 그래프 기능 확장

## 10. 기대 효과

- 여러 분기의 공시 내용을 회사별 단일 지식 페이지로 통합
- 새 공시에서 달라진 내용만 빠르게 검토
- AI 결과의 근거와 생성 이력을 추적
- 사용자 검토를 통해 잘못된 정보가 공식 지식으로 누적되는 것을 방지
- 향후 회사 간 비교, 가치사슬 분석 및 투자 리서치 에이전트의 기반 데이터로 활용
